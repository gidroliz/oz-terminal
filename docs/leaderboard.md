# Таблица рекордов

Сервер таблицы — функции Vercel в папке `api/`, данные хранятся в Redis: Upstash (REST, переменные `*KV_REST_API_URL`/`*_TOKEN` с любым префиксом) или любой Redis по адресу `REDIS_URL`.
Пока база не подключена, игра работает как обычно, а вкладка «ТОП» пишет «Таблица рекордов ещё не подключена».

## Подключение базы (один раз, ~3 минуты)

1. Открой проект **oz-terminal** на vercel.com.
2. Вкладка **Storage** → **Create Database** (или **Browse Marketplace**) → **Upstash** → **Upstash for Redis**.
3. Тариф **Free**, регион поближе к игрокам (например, **Frankfurt**) → **Create**.
4. На шаге подключения выбери проект **oz-terminal** и все окружения (Production, Preview, Development) → **Connect**.
   Vercel сам добавит переменные `KV_REST_API_URL` и `KV_REST_API_TOKEN` (или `UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN` — подходят оба варианта).
5. Переменные действуют только для новых деплоев: **Deployments** → последний деплой → **⋯** → **Redeploy**.
6. Проверь подключение: открой https://oz-terminal.vercel.app/api/health
   - `"storage":"connected"` — всё работает;
   - `"storage":"not_configured"` — сайт не видит переменные базы: проверь, что база подключена к проекту, и сделай Redeploy.
     В поле `envHints` перечислены имена похожих переменных, которые видит сайт (без значений) — по ним видно, что подключилось;
   - `"storage":"error"` — переменные есть, но база не отвечает: проверь в Upstash, что база активна.
7. Открой сайт → вкладка **ТОП**. Должно появиться «Пока никого. Будь первым!».

Бесплатного тарифа Upstash хватает с большим запасом: один взлом — это примерно 10–15 команд к базе.

## Как устроена защита от накрутки

- При старте взлома сервер выдаёт одноразовый жетон и запоминает время начала (`POST /api/run`).
- При отправке результата (`POST /api/score`) сервер проверяет:
  - заявленное время не больше реально прошедшего с выдачи жетона (+5 с запаса);
  - число этапов совпадает с режимом, в «Бесконечном» — физически достижимо (не быстрее 2,5 с на этап);
  - звёзд не больше 3 на этап, время не меньше разумного минимума для режима;
  - жетон не использован повторно и выдан для того же режима;
  - не больше 30 отправок и 120 новых взломов в час с одного адреса.
- Позывной: 2–16 символов, буквы/цифры/пробел/`._-`, грубые слова отсекаются.
- В таблице хранится только лучший результат каждого игрока. Идентификатор игрока — случайная строка в браузере, наружу не отдаётся.

Полностью защитить браузерную игру нельзя: игра идёт на устройстве игрока. Проверки отсекают подделку результата «в лоб», но не настойчивого читера. Для модерации есть админка.

## Модерация (по желанию)

1. Vercel → проект → **Settings** → **Environment Variables** → добавь `ADMIN_TOKEN` с длинным случайным значением → **Redeploy**.
2. Список игроков режима с их id:
   ```bash
   curl -H "Authorization: Bearer ТВОЙ_ADMIN_TOKEN" "https://oz-terminal.vercel.app/api/admin?mode=normal"
   ```
3. Удалить результат игрока из таблицы режима:
   ```bash
   curl -X POST -H "Authorization: Bearer ТВОЙ_ADMIN_TOKEN" \
     -d '{"action":"remove","mode":"normal","id":"ID_ИГРОКА"}' https://oz-terminal.vercel.app/api/admin
   ```
4. Сменить неприличный позывной:
   ```bash
   curl -X POST -H "Authorization: Bearer ТВОЙ_ADMIN_TOKEN" \
     -d '{"action":"rename","id":"ID_ИГРОКА","name":"Игрок"}' https://oz-terminal.vercel.app/api/admin
   ```

Режимы: `easy`, `normal`, `hard`, `alarm`, `endless`.

## API

| Запрос | Что делает |
|---|---|
| `POST /api/run` `{mode}` | Жетон нового взлома |
| `POST /api/score` `{token, id, name, mode, time, stages, broken, stars}` | Отправка результата → `{rank, total, best}` |
| `GET /api/leaderboard?mode=&id=` | Топ-50 режима и место игрока |
| `POST /api/name` `{id, name}` | Смена позывного |
| `GET/POST /api/admin` | Модерация (нужен `ADMIN_TOKEN`) |
